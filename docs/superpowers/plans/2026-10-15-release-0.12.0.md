## Order and gates

1. **Review gate.** The user reads the agents-and-providers spec (its §12 choices in particular), then both
   plans. Execution starts only after that.
2. **Plan C — agents and providers**, subagent-driven in parallel lanes where files are disjoint
   (Rust `agents/`, Rust `providers/`, TypeScript Setup rows, TypeScript composer/pane), the probe task
   first because the profile pins depend on it. Its last task is the live matrix: one real turn per agent.
   Exit: `docs(agents): agents live check …` commit (RN-4's proof).
3. **Plan B — Runs**, subagent-driven, after Plan C's Task 15 has landed (the judge consumes
   `providers::for_role`; the lanes consume `agents::project_profile` and `setup::agent_launch`). Rust
   foundations in parallel lanes (record, fence, gate, judge are disjoint files), then the scheduler, then
   the TypeScript card, then the gated end-to-end test on a throwaway project. Exit:
   `docs(runs): runs live check …` commit (RN-3's proof).
4. **The pane's live rows and the first-open look**, one session with the user at the machine
   (`c-runs/PROGRESS.md`, "Live session still to run"). Exit: `docs(runs): pane live check …` commit
   (RN-2's proof). This can happen any time before step 5 and does not block steps 2-3.
5. **Release.** Release notes drafted from the four pieces in the house voice; `./release.sh 0.12.0 "<one
   line>"` from the repo root per the release flow (signing env beside the script; `chore: v0.12.0` commit,
   tag, GitHub release with DMG, tarball, signature, OTA manifest). `RN-5` proves itself by the tag.

## What is deliberately not in 0.12.0

- The Design pane stays parked behind `DESIGN_PANE` (hidden, not removed).
- Registry agents beyond the four probed ones.
- A model picker inside the agent beyond the session's existing config option.
- Bring-your-own-key for the agent itself.
- An iOS or headless-host client (discussed 2026-10-15; parked).

## Risks that could move the date

- **Probe surprises** (Plan C Task 1): an agent whose adapter cannot run on this Mac ships as "not yet
  supported" rather than holding the release.
- **Claude Code's own start time** (1.1–4.1 s measured) caps the warm-start target; the table reports it
  as not met rather than reworking the pane.
- **The scratch worktree gate** (Plan B) on a repo with a cold cargo cache: the first gate of a run pays a
  full build; the plan shares the main target dir to avoid it, and the live check measures it.
